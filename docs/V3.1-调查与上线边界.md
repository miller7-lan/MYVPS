## 3. 服务商自动识别与管理员日程

服务商自动识别目前显示**不可用 / 等待官方文档与只读权限核验**。用户已自行在安全中心创建两条 API，但本轮没有读取密钥、调用这些 API、猜测接口、写入服务商账户或联系商家。两条 API 的权限范围、认证方法、文档、限流和响应字段均未完成核验。

接入前仍需官方证据明确：只读认证方式、实例身份字段、总量和剩余单位、计量方向、周期标识、实际重置时刻及其时区、观察时间、限流，以及欠费/超额/到期处理。没有这些证据时，系统不会伪装自动同步成功。

用户已明确选择管理员日程：**每月24日16:19，Asia/Shanghai**。这是后续明确指令对最初“只按商家周期刷新”的调整，系统将其记录为 `administrator_schedule`。这个日程不是已经核验的服务商重置时间。

两条账本保持独立：

- 管理员日程决定普通用户个人额度的周期归档与刷新。
- 服务商观察决定商家证据记录及已配置的总池保护判断。
- 人工观察、续费、赠送、升级、付费流量重置或确认商家新周期，都不会额外刷新个人额度。
- 实际商家重置需要独立周期身份和证据；同一周期重复确认不会重复入账。

服务商保留量和安全余量初始为空，表示尚未配置；界面不能把空值显示成已经确定的零字节保护。

## 4. 计量后台与原生接口验证

已在 Mac 的隔离回环环境使用官方 sing-box **1.14.4** 验证 REALITY / TUIC 的真实连接、HTTP GET/POST，以及错误凭据被拒绝；双向载荷计数通过原生 API 得到整数结果。这是本机隔离实验的证据，不能替代 VPS 上对应配置和接口的核验。

本地观察模块只允许字面量回环地址，使用认证的 `GetStartedAt` 和 `SubscribeStatus`，按生成的 Protobuf 类型解码。上传、下载和实例 epoch 使用整数，不经过浮点数；本地 HTTP 测试覆盖了大于双精度浮点精确范围的计数。

计量口径为每名用户代理进程的载荷字节。网卡总流量、vnstat、服务商账单流量和代理载荷包含的开销不同，不应互相替代。已有 vnstat 正常运行，不等于已经获得可用于个人配额的原生计量。

实例重启、计数回退、接口失败或超过允许间隔的观测缺口均需保留已有账本并进入核对状态，不把不确定增量默认为零后继续放行。普通用户计量失效时暂停；管理员不会因个人配额或计量保护被暂停。边界分配的准确性受采样间隔影响，报告需保留截止样本、缺口和完整性信息，不能宣称与服务商账单逐字节一致。

## 5. 用户、额度与授权生命周期

管理对象是用户，用户可以在多台设备使用自己的代理配置。没有固定15人限制；可用人数仍受端口、进程、CPU、内存和网络资源约束。

- 普通用户默认额度为100GB，即 `100000000000` 十进制字节；管理员个人额度无限。
- 管理员拥有独立代理身份和凭据；“个人无限”不代表服务商总流量无限。
- 新建用户默认手动禁用，准备并导入配置后再授权。
- 共享给用户的只有代理认证信息和个人配置，不共享 SSH 权限、防火墙操作权或管理密钥。
- 手动禁用、额度用尽、计量失败、总池保护和永久撤销分别保留原因；恢复一个条件不会清除其他限制。
- 加量只影响当前个人周期；下一周期清除临时加量。自动恢复不会覆盖手动禁用、永久撤销、计量失败或总池保护。
- 凭据轮换使旧认证与旧订阅令牌失效，并要求客户端重新导入。永久撤销是终态，模拟回滚也不得复活。

SQLite保存用户、载荷账本、周期、事件、撤销记录和操作幂等结果。修改请求校验状态版本，避免旧界面覆盖新状态；重复请求不会重复加量或重复执行授权。

## 6. Mac、命令行与独立调度

Mac界面与命令行通过同一套本地 RPC 和账本工作，不维护互相冲突的第二份配额状态。敏感导出和模拟收件箱采用显式操作；普通快照不包含节点凭据、完整订阅令牌或验证码。Mac界面的敏感查看还需系统身份验证。

本地调度器是独立进程，可在不启动 Mac App 的情况下处理周期、模拟运行队列和模拟邮件；已用子进程单次运行与 SQLite 重启测试验证。**关闭 App 后仍需调度进程实际运行**，不能把独立程序的存在表述为已经安装自动启动后台服务。

第一阶段没有安装 VPS systemd agent、timer 或受限 helper，也没有真实停止或启动任何线上用户代理。队列执行前重新核对当前授权、撤销、手动禁用和计量状态，旧的“启动/轮换”任务不得绕过后来的限制。线上调度、故障恢复和断线后的实际策略需要单独部署验证。

## 7. 个人导出、订阅与邮件

本地可生成 Shadowrocket、Mihomo和节点URI形式的个人模拟配置，显式标注测试环境。没有生成可用的线上个人订阅地址；本地导出不等于客户端已连接。禁用用户可显式导出用于准备，订阅响应仍拒绝禁用或撤销身份；轮换后的旧令牌拒绝访问。

订阅头中的上传、下载和总量属于该用户个人载荷配额，不是QQG商家剩余流量。订阅响应使用不缓存策略。真实个人订阅服务及其新入口尚未上线。

邮件为本地SQLite持久模拟队列，包含验证、用户/周期去重、冷却、指数重试、租约和重启恢复；只有已经验证的当前邮箱可收到普通通知。验证码哈希、过期和尝试上限已实现，普通快照不展示验证码；显式本地模拟收件箱用于完成演练。SMTP配置保存不表示认证成功，真实邮件没有发送。详细行为见 [V3.1-邮件](V3.1-邮件.md)。

## 8. 线上变更、审批与恢复边界

本轮只提供部署预览和模拟运行状态回滚。线上以下事项尚未执行，须形成具体变更清单并分别获得授权后实施：

| 后续事项 | 实施前需要确认 |
| --- | --- |
| 新用户代理及新端口 | 配置、凭据隔离、TCP/UDP可达性、客户端导入和迁移方案 |
| 新防火墙规则 | 逐项列出端口、方向、来源与恢复办法，保留当前管理通道 |
| 原生计量入口 | 固定版本兼容性、仅回环监听、独立认证、采样与失败策略 |
| 后台agent/helper/systemd | 最小权限、固定可控制对象、启动顺序、崩溃恢复与日志脱敏 |
| 服务商适配器 | 官方只读文档、最小权限、单位/周期语义和限流 |
| 真实SMTP | 凭据的私密接收方式、TLS验证和明确授权的实际测试收件人 |
| 旧共享服务迁移 | 逐名用户验证、回退路径、共享凭据退役时间；当前既有入口继续保留 |
| 证书维护 | 到期前确认续期结果与有效证书，不把当前到期记录当作续期成功 |

恢复目标是回到已知可用的**项目运行配置**。不得退回使用量、已闭合周期、操作幂等记录或邮件去重记录；不得移除永久撤销墓碑；不得恢复旧凭据使已轮换认证再次生效；不得用旧备份证书覆盖当前有效证书。

未来部署回退应仅停止本项目新增的进程/调度、恢复本项目已核验配置并重新应用当前权限。不能通过回退改写全局SSH、防火墙或其他服务，也不能把“模拟回滚通过”当作生产恢复演练完成。
