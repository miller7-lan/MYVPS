# Dazzle'VPS 私密订阅与流量显示

`subscription/` 保存本项目自行编写的订阅服务、systemd 单元和测试，使用 Python 标准库。它为已有节点提供私密订阅地址与流量估算，不负责安装代理内核，也不提供可以直接连接的公开节点。

## 使用前提

- 已有 Linux 服务器、Python 3、systemd 和正常运行的代理服务。
- 已安装并启用 vnStat 2，能够读取指定公网网卡的月统计。
- 已有受客户端信任的有效 TLS 证书，包含订阅服务器域名或公网 IP。
- 已准备自己的 Shadowrocket 配置、Clash 配置和节点链接，且已验证能连接。
- 可以开放 TCP 8443；当前代理的 TCP/UDP 443 无需调整。

仓库中的地址、节点凭据与令牌均为示例。示例 IP `192.0.2.10` 属于文档保留地址，部署时必须替换。不得将实际订阅令牌、节点凭据、证书私钥或服务器管理密钥提交到 GitHub。

## 目录与权限

建议创建独立系统用户及组 `qqg-sub`，禁用交互登录。这里的内部服务名称与已有部署保持一致，客户端可显示 `Dazzle'VPS`。

| 路径 | 所有者 | 权限 | 用途 |
| --- | --- | --- | --- |
| `/opt/qqg-sub/server.py` | root:root | 0755 | 服务程序 |
| `/etc/qqg-sub/` 及子目录 | root:qqg-sub | 0750 | 只读配置目录 |
| `/etc/qqg-sub/config.json` | root:qqg-sub | 0640 | 私密令牌及文件映射 |
| `/etc/qqg-sub/clients/` 内配置文件 | root:qqg-sub | 0640 | 节点和规则 |
| `/etc/qqg-sub/tls/cert.pem` | root:qqg-sub | 0640 | 完整证书链 |
| `/etc/qqg-sub/tls/private.key` | root:qqg-sub | 0640 | 证书私钥 |
| `/var/lib/qqg-sub/` | qqg-sub:qqg-sub | 0700 | 持久化用量状态 |

服务用户需要读取配置，因此配置采用 root 所有、服务组可读的权限；服务用户不能修改令牌、节点或证书。systemd 单元会创建状态目录。

## 配置与部署

1. 将 `subscription/server.py` 安装到 `/opt/qqg-sub/server.py`。
2. 将 `config.example.json` 复制到服务器的 `/etc/qqg-sub/config.json`，填写真实网卡、证书路径及客户端文件路径。示例启用 Base64 节点订阅和剩余量状态行。
3. 用安全随机数生成独立令牌，例如 Python 的 `secrets.token_urlsafe(36)`。每台设备建议使用不同令牌。令牌必须为 32–128 位 URL 安全字符；示例占位文本不能用于正式部署。
4. 将已验证的客户端配置放入上述目录；`nodes.txt` 为换行分隔的原始节点 URI，服务会自动进行 Base64 编码。
5. 使用服务身份验证读取统计：`runuser -u qqg-sub -- /usr/bin/vnstat --json m -i ens17`。实际网卡不一定是 `ens17`，应与配置一致。
6. 将 `qqg-sub.service` 安装到 `/etc/systemd/system/`，重新加载 systemd 后启用服务。仅开放所需的 TCP 8443，并保留原有代理、SSH 和证书验证端口。
7. 使用客户端验证 HTTPS 证书、200 响应及 `Subscription-Userinfo` 响应头。未授权路径应返回 404。请勿使用忽略证书错误的选项作为正式连接方式。

地址形式如下，其中 `YOUR_PRIVATE_TOKEN` 是说明占位符：

```text
https://192.0.2.10:8443/YOUR_PRIVATE_TOKEN/nodes.txt
https://192.0.2.10:8443/YOUR_PRIVATE_TOKEN/config.conf
https://192.0.2.10:8443/YOUR_PRIVATE_TOKEN/clash.yaml
```

Shadowrocket 首页添加 `nodes.txt` 为订阅，并将名称设为 `Dazzle'VPS`；规则配置单独导入 `config.conf`。Clash Verge Rev 将 `clash.yaml` 作为远程配置导入。刷新订阅时更新用量信息，客户端是否定时刷新取决于其自身设置。

`expire` 为可选 Unix 时间戳，只能填写已经核实的产品到期时间；示例不虚构到期日期。某些客户端版本只有收到完整到期字段时才显示流量卡片，应在核实商家信息后填写。

## 剩余量显示与统计口径

所有设备共享一个默认 500,000,000,000 字节的总量。服务读取当前 UTC 日历月的公网网卡 RX 和 TX，响应头包含 `upload`、`download`、`total`，可选 `expire`。这不是商家官方的计费接口，也不是每台设备各有 500GB。

网卡收发统计会包含代理、SSH、系统更新和证书流量；商家可能仅计单向、采用不同 GB 单位或不同重置日。vnStat 安装前的用量无法追溯。因此 App 显示的是全服务器共享估算，官方余额、重置周期和超额规则以商家后台为准。部署前确认 vnStat 月重置日为 1 且服务器时区为 UTC；否则需要调整统计选择逻辑。

启用 `usage_status_node: true` 后，只有 `nodes.txt` 会额外增加一个状态行，例如：

```text
剩余 497.50 GB / 500 GB（全设备估算）
```

状态行复用第一个有效 VLESS 节点，仅更改显示名称，因此它可以正常连接。原有两个节点保留原顺序和名称；状态行用于展示用量，日常仍选择“常用”或“迅速”节点。剩余量最低显示 0，不会出现负数。该功能默认关闭，示例配置明确开启；规则配置和 Clash 配置正文不受影响。

## 安全与稳定性

- TLS 最低版本为 1.2，使用真实证书，不跳过验证。
- 按设备独立随机令牌和精确路径匹配，无目录浏览，不记录请求路径、令牌或客户端地址。
- 每个来源地址每分钟最多 100 次请求；来源记录和并发线程数量有上限，连接及统计读取均有超时。
- 程序由独立低权限用户运行，systemd 限制写入位置、权限、内存与任务数量。
- 统计缓存 30 秒，同月已读用量不回退，并持久化保存。统计暂时失败时继续使用有效缓存；从未取得有效当月数据时返回 503，不伪造零用量。采集故障期间，缓存可能暂时低估实际用量。
- 订阅 URL 是持有即可访问的凭据，不能公开分享或写入公共日志。撤销某个设备的令牌不等于撤销其代理凭据；两者需分别管理。

## 证书续期

Python 服务启动时加载证书，证书续期成功后需要安全地复制新证书链和私钥到专用目录，再重启 `qqg-sub.service`。这只重启订阅服务，不中断已有代理连接。

续期钩子应先核验证书名称或 IP、有效期及证书私钥配对，再以最终权限暂存并原子替换；不要向仍在使用的证书文件直接截断写入。证书签发及续期计划应由现有受维护工具管理，本服务不自动申请证书。

已有 sing-box 1.14.4 的文件证书支持热更新，但是否无需重启取决于内核及配置，应依据其官方文档和实际连接验证。不要给任意代理程序假设相同能力。

## 本地验证

```bash
cd subscription
python3 -m unittest -v test_server.py
```

测试使用临时文件、回环网络和虚构凭据，覆盖订阅响应、拒绝路径、用量读取失败、缓存、持久化、跨月、单调统计、限流及状态行。测试通过不代表新服务器已部署，还需完成上述远端权限、证书及真实客户端连接验证。
