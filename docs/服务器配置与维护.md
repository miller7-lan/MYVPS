# 服务器配置与维护

这些文件记录已采用的部署结构，供重建、审查和手动维护。它们不是无人值守的一键安装器。公开模板中的 `192.0.2.10` 为文档地址，UUID、密码和 REALITY 参数均不能用于正式部署。

## 参数与生成

使用官方 sing-box 1.14.4 二进制，并按其发布资产校验值验证下载。本文记录已验证的版本，升级前应检查配置兼容性及新的连接测试结果。

```sh
sing-box generate reality-keypair
```

将新生成的私钥、公钥填入本地 `private/deployment.json`。为 Mac、iPhone、Windows 各自生成不同的 VLESS UUID、TUIC UUID 与 TUIC 密码，例如在本地使用 Python `uuid.uuid4()`、`secrets.token_urlsafe(32)`；短 ID 可用 `secrets.token_hex(8)`。不要复用仓库示例。UUID 本身在这里也是认证凭据。

填写实际 IPv4、VLESS/TUIC 端口、REALITY 握手目标 `reality_sni`、TUIC 证书对应域名或 IP `tuic_server_name`。握手目标需从服务器验证 TLS 兼容性，不要只照抄示例域名。

生成器 `scripts/render.py` 输出服务端、每设备的 URI / Shadowrocket / Mihomo 配置。`scripts/merge_base.py` 可将自己的基本规则合并进客户端配置；原规则顺序保留，Mihomo 不支持的 USER-AGENT 和 URL Rewrite 有转换限制。输出均含真实凭据，只能保存在本地私密目录。

## 服务目录

| 路径 | 用途 |
| --- | --- |
| `/etc/s-box/sing-box` | 官方核心二进制，root 所有 |
| `/etc/s-box/sb.json` | 生成的服务端配置，root:sing-box 0640 |
| `/etc/s-box/cert.pem` | TUIC 的完整证书链 |
| `/etc/s-box/private.key` | 证书私钥，root:sing-box 0640 |
| `/var/lib/sing-box` | 服务工作目录，独立 sing-box 用户可写 |

建立不可交互登录的 `sing-box` 系统用户。`/etc/s-box` 使用 root:sing-box 0750。证书和配置必须对服务用户可读，但不允许该用户修改。

将 `server/systemd/sing-box.service` 安装到 `/etc/systemd/system/`，先执行配置检查：

```sh
/etc/s-box/sing-box check -c /etc/s-box/sb.json
systemctl daemon-reload
systemctl enable --now sing-box
systemctl status sing-box --no-pager
```

该服务具备异常重启和权限限制。修改配置前备份；人工重启会中断当时连接。

## 证书和续期

TUIC 与订阅 HTTPS 都必须使用被客户端信任、名称或 IP 匹配的证书，不跳过校验。已采用 Let’s Encrypt 公网 IP 短期证书与 Certbot；新建部署必须自行完成当前受支持的申请流程。80/TCP 应保持能接收证书 HTTP 验证。

续期示例单元使用 `/opt/qqg-certbot/bin/certbot`，证书名 `qqg-ip`、目录 `/etc/letsencrypt/live/qqg-ip`。若实际路径或名称不同，需同步修改 service 和钩子。`qqg-` 只是内部名称。

`server/hooks/renew-certificate.sh` 先验证证书 IP、有效期及私钥配对，再原子替换证书。安装前必须把其中 `SERVER_IP` 改成实际 IP；Certbot 自动运行钩子时通常没有自定义环境变量，因此应在安装副本里写入正确地址。保留仓库示例副本脱敏。

将配置好的副本安装到 `/etc/letsencrypt/renewal-hooks/deploy/qqg-sing-box`，仅 root 可执行。部署两个续期单元后启用 `qqg-certbot-renew.timer`，每天两次检查。执行 `certbot renew --dry-run` 验证流程，再以当前正式证书演练部署钩子并复测连接。

sing-box 1.14.4 监听证书文件所在目录，支持有效证书对热重载。此钩子不重启代理；Python 订阅服务会重启以加载证书。修改证书后仍需确认代理进程未改变、TUIC 新连接有效。[官方 TLS 文档](https://sing-box.sagernet.org/configuration/shared/tls/#certificate_path)

## 基础安全与稳定性

`server/hardening/` 分别提供 SSH、日志、安全更新与内存参数示例，请先检查机器已有配置再合并，避免覆盖其他服务设置。

- 密钥登录：先确认另一条 SSH 连接可使用新密钥登录，再关闭密码认证。已有 `sshd_config` 的优先级会影响配置，应用前执行 `sshd -t` 和 `sshd -T`。
- 防火墙：仅按实际用途开放 SSH TCP 22、证书验证 TCP 80、VLESS TCP 443、TUIC UDP 443、私密订阅 TCP 8443。不要清空已有防火墙规则或关闭防火墙。没有订阅服务时不需要 8443。
- 日志：持久日志最多 100MB，运行时日志最多 50MB，保留不超过 7 天，避免占满小磁盘。
- 内存：1GB 内存机可配置 1GB 应急交换空间和 swappiness=10。创建前检查已有交换空间，不要格式化已有文件。
- 更新：使用 Ubuntu 原有安全更新来源，关闭自动重启。内核更新要求重启时，选择空闲时间手动维护。
- QUIC 缓冲参数是配置示例，不修改路由、端口或拥塞算法，也不代表线路延迟和丢包一定改善。

## 常用检查

```sh
systemctl status sing-box qqg-sub vnstat --no-pager
systemctl show sing-box -p NRestarts -p MemoryCurrent
systemctl list-timers qqg-certbot-renew.timer --no-pager
vnstat -m -i ens17
free -m
df -h /
journalctl -u sing-box -n 30 --no-pager
```

网卡不一定叫 ens17，应以实际配置为准。握手或目标连接错误要结合具体请求判断，不凭一条日志认定整台服务器故障。长期稳定性仍需真实网络、多日晚高峰和完整服务功能验证。
