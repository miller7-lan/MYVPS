## 修复与恢复

首次启动发现新数据库 WAL 分叉：直接打开、关闭已有数据库的原始文件描述符，可能释放同进程 SQLite 在 Linux 上持有的文件锁。已备份当前数据库及尚被进程持有的脱离目录 WAL/SHM，暂停新增组件，发布最小修复版本。

首次锁修复版本为 `7b59b5cc8f22804c98211690`，当前版本见下方邮件与删除功能记录。修复后 Linux 六项文件锁回归通过，数据库 quick_check 为 ok，后台没有持有已删除的数据库文件。保留原始备份和修复收据；不要将程序指针直接退回存在锁缺陷的旧版本。

需要撤回新程序时，使用项目范围的停用方案，保留账本、永久撤销记录及有效证书，继续使用原 443 / 8443 入口。不得删除 WAL 或用旧数据库恢复为零用量。

## Clash 导入入口修复

用户反馈导入失败，确认使用的地址末尾是`nodes.txt`。该路由返回Base64节点列表，而完整Clash/mihomo配置位于`config.yaml`。原App即使选择Mihomo导出，复制和二维码仍优先选择nodes_url，因而提供了错误格式。

修复后Mihomo默认选择「Clash订阅」，复制链接和二维码共用经过验证的`config.yaml`选择逻辑，缺失或格式不符时不回退到节点列表；Shadowrocket的订阅与规则入口另行标明。新增五项导出格式测试，Swift合计41项通过。

线上两用户的完整配置均通过严格HTTPS读取（200）与官方mihomo v1.19.33配置校验。用户将原链接末尾改为`config.yaml`后确认导入成功。本次仅更新Mac App，没有更改服务器、凭据或重启代理；这不代表之前记录的GitHub网络波动已获长期验收。

用户随后反馈Clash客户端无法连接，当前正在单独诊断。上述隔离CLI成功记录不等于用户当前Clash客户端已通过验收，最终客户端体验仍待确认。
