# Dazzle'VPS V3.1：第一阶段本地使用

这版提供可运行的原生 macOS App 和本地后台逻辑。所有用户、凭据、额度与邮件操作默认写入独立模拟数据库；真实 VPS 入口只允许固定的只读 SSH 检查。不会重启现有代理、安装线上后台或修改防火墙、SSH、商家账户。新建本地用户不等于已在 VPS 授权。

## 启动与数据

运行交付的 `DazzleVPS.app`。需要 macOS14+、Apple Silicon 和 Python3.11+；当前机器已完成实际构建与启动。应用使用本机临时签名，没有 Developer ID 公证；其他机器应从源码构建并自行验证来源。

数据位于 `~/Library/Application Support/DazzleVPS/Simulation/state.sqlite3`，数据库0600，目录0700。首次为空，不会自动导入历史三台设备或自动给新设备权限。“创建隔离示例”仅用于空库中的演示。用户属于账号授权，不绑定硬件；复制有效节点凭据会让复制者以同一用户身份使用额度。

- 概览：代理服务未部署、商家资料可信状态、个人载荷合计、管理员计划周期、邮件状态。
- 用户：普通用户默认100GB/周期、管理员专属凭据不限个人额度；可编辑、追加、停用、恢复、轮换或永久撤销。管理员不限量仍受商家实际套餐约束。
- 设置 → 额度与周期：默认每月24日16:19 Asia/Shanghai，这是管理员规则。QQG归零日期仅历史面板记录，不能视为时刻、时区和重置事件已核实。
- 通知：填写模拟SMTP和邮箱，发送模拟验证邮件；通过系统身份验证查看本地模拟收件箱，再填写验证码。实际不会向任何邮箱发送邮件。
- 设置 → 恢复与记录：查看部署与回滚预览。模拟回滚保留用量、周期和永久撤销状态。
- 设置 → 连接：输入现有主机与选择现有私钥，只读取固定的服务/版本/内存/监听摘要和证书到期时间。不复制私钥，不自动接受未知或变更的主机密钥，也不更新known_hosts。

敏感操作使用macOS系统身份验证。系统可能认可已有身份而不显示新的Touch ID提示；不能把“未弹窗”视为代码绕过。取消或无法验证时停止操作。当前登录的Mac用户能直接访问本地数据库，App不是针对同一系统账户恶意程序的隔离沙箱。

## 用户授权及导出

新增用户默认手动停用；启用后，普通用户还须取得可信初始计量基线。模拟模式没有线上采集器，所以界面显示等待计量属于正常保护状态。管理员也需明确启用，但不因共享用户计量失败被自动暂停。

用户详情可导出：Shadowrocket原生配置、mihomo兼容YAML（实际使用YAML1.2兼容的JSON表示）、两个独立节点URI及二维码。文件保存权限0600；凭据默认隐藏，显式导出需系统身份确认。复制的敏感内容在剪贴板未改变时60秒后清除。

**第一阶段导出使用192.0.2.10保留测试地址及公开测试REALITY公钥，不能连接真实VPS。** 没有部署新订阅端点，因此线上订阅URL为空，界面显示待部署。现有已交付的个人订阅与443入口不变。

正式上线后，用户的订阅Token与两种协议认证一同轮换/撤销；订阅响应逻辑已在本地测试，剩余量采用该用户的代理载荷额度，不冒充商家余额。导入Shadowrocket需分别选择节点URI/二维码或完整配置；Clash Verge Rev等须使用支持VLESS REALITY/TUIC的mihomo核心。旧版Clash不保证支持。真实客户端导入和公网连接留待部署验收。

## CLI

安装：`python3 scripts/install_cli.py`，生成 `~/.local/bin/dazzle-vps` 及独立源码包。修改后端后重新执行安装。无需全局pip依赖；本地模拟使用Python标准库。

```sh
dazzle-vps --help
dazzle-vps --json --dry-run doctor
dazzle-vps --json list
dazzle-vps --json resolve "某个用户名称"
dazzle-vps --json --dry-run request deploy.preview
```

所有参数选项放在子命令前。读取快照返回当前 `revision`，修改时使用相同的预期版本；冲突后重新读取并核对，不自动重试写操作：

```sh
dazzle-vps --json snapshot
dazzle-vps --json --expected-revision 1 --dry-run user add --name "本地测试用户"
```

把示例中的1替换为实际revision，去掉`--dry-run`才写入模拟库。用户命令有`add/enable/disable/revoke/rotate/export/update/topup`，另有`status/list/resolve`。原始域动作通过`request ACTION --params JSON`；或者`rpc`从标准输入读取一个JSON请求，便于App传输，避免凭据出现在命令参数中。

JSON固定返回`{ok,request_id,revision,data,error}`，失败使用非零退出码；错误消息脱敏。RPC成功修改有持久请求幂等缓存；秘密导出和模拟邮箱内容只暂存于内存，不保存进请求缓存。不要把敏感导出重定向到共享目录。

## 本地后台与测试

建立隔离环境后运行：

```sh
uv venv .venv
uv pip install --python .venv/bin/python './backend[native]'
PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests -v
python3 -m unittest discover -s subscription -p test_server.py -v
bash macos/test-app.sh
bash macos/build-app.sh
```

这里保留显式PYTHONPATH，以避开某些macOS环境对editable `.pth`文件的处理差异；实际App使用随包后端，CLI使用独立源码包，不依赖editable安装。

后台独立于Mac App。以下命令仅操作指定模拟库，不上传、不安装systemd，也不会启动真实代理：

```sh
PYTHONPATH=backend .venv/bin/python -m dazzle.agent --state-dir /tmp/dazzle-review --once
PYTHONPATH=backend .venv/bin/python -m dazzle.agent --state-dir /tmp/dazzle-review --interval 1 --iterations 3
```

测试时间注入仅模拟允许，例如追加`--once --at 2026-11-24T08:19:00Z`。持续运行的模拟agent会把超过5秒未更新的普通用户计量标为故障；它不会伪造采集数据。结束终端中的模拟agent不影响现有线上服务。

Native API使用官方1.14.4协议投影生成的Protobuf，只有可选`native`依赖需要protobuf。更新协议需核对官方proto后生成，不手写整数解码器：

```sh
uv pip install --python .venv/bin/python 'grpcio-tools==1.84.1'
.venv/bin/python -m grpc_tools.protoc -I backend/dazzle/proto --python_out=backend/dazzle/proto backend/dazzle/proto/traffic.proto
```

协议投影及生成源码保留上游许可说明，见`third_party/NOTICE.md`。本地协议烟测需要明确传入已验证来源和摘要的sing-box1.14.4二进制，不会自动下载安装：

```sh
PYTHONPATH=backend .venv/bin/python scripts/verify_native_local.py --sing-box /完整路径/sing-box
```

## 当前限制

- 未创建线上用户实例、未批准新端口，现有443三组凭据未迁移。
- QQG API虽已由管理员创建，但文档、权限、流量字段、限频和计费口径未核实；不读取密钥、不猜接口、不复用浏览器Cookie。
- 没有真实SMTP配置；TLS流程与错误通过mock测试，真实投递未验证。
- 每秒计数写SQLite，明细按用户/周期/实例/分钟聚合。采样与停用存在延迟，跨边界可能有不超过可信采样窗口的归属误差；不是字节级硬限额。
- 大于5秒的计量缺口、重启和倒退保留账本并要求对账，未知用量不视为零；恢复共享用户不能绕过其他停用原因。
- 1GB VPS不支持无限实例并发。无固定用户数上限，正式部署需测量实际资源成本。

## 界面优化版

一级导航收为概览、用户、通知、设置。概览展示上传/下载环形图、用户用量条与管理员刷新进度；点击用户行直达详情。用户详情的导出、加量为就地弹层，编辑默认只展示名称、额度、邮箱。进阶设置、SMTP与原始技术数据按需展开。商家数据未验证或过期时不绘制容量图，也不会根据历史展示值生成趋势。
