# V3.1 本地邮件模拟

第一阶段的所有邮件操作只读写本地状态目录里的 SQLite 数据库，不连接 SMTP、不认证、不向外部邮箱发信。`configured: true` 只表示配置格式已保存，`transport: simulated` 和 `connected: false` 明确表示没有测试外部服务。未配置时 `configured: false`，处理队列返回 `state: not_configured`。

## 邮箱验证与通知

`mail.configure` 接受 `host`、`port`、`security`（`ssl` / `starttls`）、`username`、`sender` 和 `admin_email`。公共 RPC 不接受 SMTP 密码或真实发送模式。

`mail.verify.send` 接受 `{user_id?, email?}`；省略用户时验证配置中的管理员邮箱。验证码为六位随机数字，十分钟有效，最多尝试五次；同一身份每分钟最多重新生成一次。验证表只保存加盐 PBKDF2 哈希。实际模拟邮件内容保存在独立的 `mail_simulated_mailbox` 表，普通快照、队列和验证发送响应不包含正文、验证码或验证哈希。

用户可在本地界面通过系统身份验证后显式查看模拟收件箱，从中取得验证码，完成本地演练。`mail.simulated_inbox` 是只读的敏感响应，仅模拟模式可调用，需校验当前状态版本，不写入持久 RPC 响应缓存。它返回 `sensitive: true` 和本地模拟邮件正文；无论邮件是否已由 `mail.process` 标记处理，都明确表示没有向外部发送。这个入口不返回任何代理凭据。模块内测试也可使用 `simulated_mailbox_for_tests` 检查邮件。

`mail.verify.confirm` 接受 `{user_id?, code}`。错误或过期返回 `verified: false` 和原因；错误次数写入同一个调用事务，避免异常回滚把尝试次数清零。更换邮箱会清除用户验证状态；更换管理员邮箱会清除管理员邮箱验证。管理员通知邮箱与管理员用户的邮箱分别验证。

只有已经验证的当前邮箱可以排入普通通知。发送前会再次检查邮箱、撤销状态和验证状态，防止队列中的旧地址继续接收。验证邮件是这个限制的必要例外，它只能进入待验证的目标邮箱。

`mail.test` 只产生标准测试内容，不接受任意正文或凭据。普通通知写入前会移除代理链接、订阅链接、密码、令牌、Authorization 和私钥；生产事件仍应仅传递额度、用户显示名、周期等必要信息，不应传递任何代理凭据。

## 持久队列

`mail_outbox` 保存通知状态，事件按用户、周期和事件键去重。默认通知开启、同类通知冷却一小时、最多尝试五次；`mail.preferences` 可设置 `enabled`、`cooldown_seconds`（0–86400）和 `max_attempts`（1–10）。验证码另外固定一分钟冷却、五次验证上限。

`mail.process` 处理最多100封到期消息，默认20封。模拟成功状态为 `simulated`，不会显示成已经实际发送。失败在60秒后重试，之后间隔按指数增长，最大一小时；不可重试错误或达到尝试上限进入 `dead`。只记录固定错误码，不记录 SMTP 返回、异常正文或请求载荷。

队列租约记录 worker、到期时间和尝试次数；租约到期可被新 worker 恢复，旧 worker 不能提交结果。重启不清空队列、去重键、尝试次数或验证状态。本地模拟邮箱以消息 ID 唯一，重复处理不会产生第二封模拟邮件。

事务由外部 RPC / worker 管理，邮件模块不主动提交。`claim_messages` 和 `finish_message` 供未来 worker 分阶段提交租约使用；第一阶段 `mail.process` 在现有 RPC 事务中完成模拟。

## TLS 适配器边界

内部 `_smtp_send` 提供 SMTPS 和 STARTTLS submission 的后续接入结构，使用系统可信 CA、验证证书与主机名，STARTTLS 成功后才允许认证；TLS 失败不会退回明文。默认 `allow_live: false`。公共 RPC 和本地 worker 均不调用该适配器，第一阶段没有密码接收路径。相关验证只使用 mock SMTP 对象，不建立任何网络连接。
